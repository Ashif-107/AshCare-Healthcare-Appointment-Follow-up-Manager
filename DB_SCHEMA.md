# Database Schema Definition

Our backend uses **SQLModel** to define and interact with the PostgreSQL database. The exact definitions are located in `backend/app/models.py`.

Below is the breakdown of the tables, columns, and relationships in our schema.

## 1. `user` Table
The central table for authentication and identity.

| Column Name | Data Type | Modifiers | Description |
| :--- | :--- | :--- | :--- |
| **id** | Integer | Primary Key | Unique identifier. |
| **email** | String | Unique, Indexed | Used for login. |
| **full_name** | String | | The user's full name. |
| **role** | Enum | | `ADMIN`, `DOCTOR`, or `PATIENT`. |
| **hashed_password** | String | | Bcrypt hashed password. |

*Relationships:*
- A User can have one `DoctorProfile` (if role is DOCTOR).
- A User can have many `Appointment` records (as a patient or doctor).

## 2. `doctorprofile` Table
Extended information specifically for doctors.

| Column Name | Data Type | Modifiers | Description |
| :--- | :--- | :--- | :--- |
| **id** | Integer | Primary Key | Unique identifier. |
| **user_id** | Integer | Foreign Key, Unique | Links to `user.id`. |
| **specialization** | String | | e.g., "Cardiologist". |
| **working_hours_start** | Time | | e.g., 09:00:00. |
| **working_hours_end** | Time | | e.g., 17:00:00. |
| **slot_duration_minutes**| Integer | | Default is 30 minutes. |

*Relationships:*
- Belongs to one `User`.
- Can have many `Leave` days.

## 3. `leave` Table
Tracks days a doctor is unavailable for bookings.

| Column Name | Data Type | Modifiers | Description |
| :--- | :--- | :--- | :--- |
| **id** | Integer | Primary Key | Unique identifier. |
| **doctor_id** | Integer | Foreign Key | Links to `doctorprofile.id`. |
| **leave_date** | Date | | The specific day the doctor is on leave. |
| **reason** | String | Optional | Reason for the leave. |

## 4. `appointment` Table
Handles the core booking flow, including the temporary "Slot Hold".

| Column Name | Data Type | Modifiers | Description |
| :--- | :--- | :--- | :--- |
| **id** | Integer | Primary Key | Unique identifier. |
| **patient_id** | Integer | Foreign Key | Links to `user.id`. |
| **doctor_id** | Integer | Foreign Key | Links to `user.id`. |
| **start_time** | Datetime | Indexed | The beginning of the slot. |
| **end_time** | Datetime | | The end of the slot. |
| **status** | Enum | | `HOLD`, `CONFIRMED`, `CANCELLED_DUE_TO_LEAVE`, or `COMPLETED`. |
| **hold_expires_at** | Datetime | Optional | Determines when a `HOLD` slot becomes available again. |

*Relationships:*
- Belongs to a Patient (`User`) and a Doctor (`User`).
- Can have one `ConsultationNote`.

## 5. `consultationnote` Table
Stores AI-generated summaries and clinical notes for an appointment.

| Column Name | Data Type | Modifiers | Description |
| :--- | :--- | :--- | :--- |
| **id** | Integer | Primary Key | Unique identifier. |
| **appointment_id** | Integer | Foreign Key, Unique | Links to `appointment.id`. |
| **symptoms** | String | | Provided by the patient during booking. |
| **pre_visit_summary** | String | Optional | Generated by LLM for the doctor to read before the visit. |
| **urgency_level** | String | Optional | Extracted by LLM (Low/Medium/High). |
| **suggested_questions** | String | Optional | Generated by LLM. |
| **post_visit_notes** | String | Optional | Clinical notes submitted by the doctor after the visit. |
| **prescription** | String | Optional | Submitted by the doctor. |
| **post_visit_summary** | String | Optional | Patient-friendly translation generated by LLM after the doctor submits notes. |
